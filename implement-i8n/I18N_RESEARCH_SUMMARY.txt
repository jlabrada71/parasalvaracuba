KEY FINDINGS

1. OFFICIAL RECOMMENDATION: Use @nuxtjs/i18n Module (NOT Plain Vue-i18n)

   Why?
   - Official Nuxt team support
   - Built-in locale routing with URL prefixes (/en/, /es/)
   - SEO features (hreflang, og:locale)
   - Automatic browser language detection
   - Cookie-based persistence
   - Server-side rendering (SSR) support
   - Auto-imports for useI18n()
   - Lazy-loading support for performance

   Current Project Issue:
   - ❌ Using manual Vue-i18n plugin instead of module
   - ❌ Not using locale routing features
   - ❌ Manual localStorage instead of cookies
   - ❌ Missing advanced i18n functionality

2. ROUTING STRATEGIES (Choose One)

   'prefix_except_default' ← RECOMMENDED for parasalvaracuba.org
   - Default locale: /about (no prefix)
   - Other locales: /en/about, /pt/about
   - Why: Spanish is primary, others clearly prefixed

   'prefix'
   - All locales: /es/about, /en/about, /pt/about
   - Use when all locales should be equal

   'prefix_and_default'
   - Both: /about AND /es/about
   - Use when need flexibility

   'no_prefix'
   - Routes: /about (all locales)
   - Locale detected via cookie/browser/manual
   - Use when hiding locale from URL

3. AUTO-IMPORTS WITH NUXT 4

   ✅ Automatic with @nuxtjs/i18n module:
   const { t, locale, useLocalePath } = useI18n()
   // No import statement needed!

   Why it works:
   - Module registers auto-imports via Nuxt's auto-import system
   - Works because Auto-imports enabled (default)
   - Only works with the module, not manual plugin

4. LOCALE SWITCHING & PERSISTENCE

   - Cookie-based persistence (automatic)
   - Browser language detection (automatic)

================================================================================
COOKIE PERSISTENCE DETAILS
================================================================================

What Gets Set:
Cookie Name: parasalvara_locale (configurable)
Value: Current locale code (e.g., 'es', 'en', 'pt')
Expires: 365 days (configurable)
Scope: Root domain

When It's Used:
1. First visit: Browser language detection
2. After locale change: Cookie updated
3. Page refresh: Cookie checked, locale restored
4. Across sessions: Cookie persists for 365 days

No Server-Side Needed:
- Module handles cookie automatically
- No manual localStorage needed
- Secure cookie handling
- Works with SSR

================================================================================
PERFORMANCE CONSIDERATIONS
================================================================================

With Lazy Loading:
- Total bundle size: ~2-3% smaller per locale
- Initial load: Baseline + current locale only
- Locale switch: Download new locale messages (~5-50KB)
- Recommended for: Apps with 10+ locales or large message files

Current Project:
- 3 locales only
- Small message files (~3-5KB each)
- Lazy loading: Optional (not critical)
- Recommendation: Enable for future-proofing
